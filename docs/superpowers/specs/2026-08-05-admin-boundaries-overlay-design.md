# ชั้นข้อมูลเขตเทศบาลบนแผนที่ 3 มิติ (overlay อ้างอิง)

วันที่: 2026-08-05
สถานะ: implement แล้ว (ปรับสเปกตามข้อมูล OSM จริง 2026-08-05)

## ปัญหาที่แก้

ผู้ตรวจ/โรงเรียนดูแผนที่ 3 มิติแล้วไม่รู้ว่าจุดที่ตั้งอยู่ในหรือนอกเขตองค์กรปกครองส่วนท้องถิ่น
ประเภทไหน (เทศบาลนคร/เทศบาลเมือง/เทศบาลตำบล/อบต.) ทั้งที่เป็นบริบทสำคัญของความเป็น
เมือง/ชนบทของพื้นที่

## ข้อตกลงที่เคลียร์แล้วกับผู้ใช้

1. **เป้าหมาย: overlay อ้างอิงเท่านั้น** — วาดเส้นเขตให้เห็นบนแผนที่ ไม่ผูกกับคะแนน
   ไม่บันทึกลงฐานข้อมูล และ**ไม่แตะ** `GisAutoScore.components.borderMunicipality`
   (ยังเป็น `null` ตามเดิม — จะเติมได้ต้องมีข้อมูลระดับตรวจสอบได้เพื่อให้คะแนน ไม่ใช่ overlay)
2. **ขอบเขตพื้นที่: รอบจุดวิเคราะห์เท่านั้น** — ดึงสดจาก OSM เมื่อผู้ใช้เปิดชั้นข้อมูล
   ไม่ pre-compute ทั้งประเทศ (ไฟล์ใหญ่หลายสิบ MB เกินความจำเป็นของ overlay)
3. **อบต. ไม่มี polygon ใน OSM** — พื้นที่ อบต. คือพื้นที่ตำบลส่วนที่ไม่อยู่ในเขตเทศบาล
   ข้อสรุป: **วาดเฉพาะเขตเทศบาล** (ไม่วาดเขตตำบลแทน — ตำบลเดียวคร่อมได้ทั้งเทศบาลและ อบต.
   จะสื่อความหมายผิด)

   ⚠️ **แก้ข้อสรุปเดิม (2026-08-05 หลังตรวจข้อมูลจริง)**: เดิมสเปกนี้ให้ UI บอกว่า
   "นอกเขตเทศบาลทุกแห่ง = เขต อบต." — **ยกเลิกข้อความนั้น เพราะเป็นการอ้างที่ผิด**
   OSM มีขอบเขตเทศบาลไทยไม่ครบ การไม่พบเส้นเขตจึงแปลได้แค่ "ไม่มีข้อมูล" ไม่ใช่ "ไม่ใช่เขตเทศบาล"
   (ดูหัวข้อ "ความครอบคลุมของข้อมูล OSM" ด้านล่าง)
4. **เทศบาลที่ OSM มีแค่หมุด → แสดงเป็นหมุดพร้อมระบุว่าไม่มีขอบเขต** ไม่ซ่อน และไม่วาด
   วงกลมสมมติแทนขอบเขต (จะกลายเป็นการกุขอบเขตที่ไม่มีข้อมูลรองรับ)

## โมดูลใหม่: `lib/map/adminBoundaries.ts`

client-safe (ห้าม import cesium — แบบเดียวกับ `lib/map/borders.ts`/`mapApi.ts`)

```ts
export type AdminKind = "nakhon" | "mueang" | "tambon" | "special";

export interface AdminBoundary {
  name: string;              // ชื่อเต็ม — official_name ถ้ามี ไม่งั้น name
  kind: AdminKind;
  rings: [number, number][][]; // [lng,lat][] ต่อ ring (เฉพาะ outer); ว่างเมื่อมีแค่หมุด
  pointOnly: boolean;        // true = OSM มีแค่หมุด ไม่มีขอบเขต
  labelLat: number;          // centroid ของ ring ใหญ่สุด หรือพิกัดหมุด
  labelLng: number;
}

fetchAdminBoundaries(lat, lng, radiusM, signal): Promise<AdminBoundary[]>
classifyAdminKind(name: unknown): AdminKind | null
parseOverpassAdminBoundaries(json: unknown): AdminBoundary[]   // pure — ตัวที่เทสต์
```

- **Overpass query**: union 4 ชุดใน bbox สี่เหลี่ยมครอบรัศมี `ADMIN_FETCH_RADIUS_M = 15_000`
  รอบจุดวิเคราะห์ แล้ว `out geom` — `relation[boundary=administrative]` ที่ `name` **หรือ**
  `official_name` ขึ้นต้นว่า "เทศบาล" และ `node[place]` ด้วยเงื่อนไขชื่อเดียวกัน
  (เหตุผลของทั้งสองข้อ ดูหัวข้อ "ความครอบคลุมของข้อมูล OSM")
- **endpoint หลัก + สำรอง** ชุดเดียวกับ `scripts/fetch-borders.mjs`
  (overpass-api.de → overpass.kumi.systems) — ลองตัวถัดไปเมื่อ 429/5xx/ล้มเหลว
- **`classifyAdminKind`** จากคำนำหน้าชื่อไทย: `เทศบาลนคร…` → `nakhon`,
  `เทศบาลเมือง…` → `mueang`, `เทศบาลตำบล…` → `tambon`,
  `กรุงเทพมหานคร`/`เมืองพัทยา` → `special`; ชื่อไม่เข้าเค้า → `null` = ทิ้งรายการนั้น
  (อย่าเดา — แสดงผิดแย่กว่าไม่แสดง) โดยอ่าน `official_name` ก่อน แล้วถอยไป `name`
- **validate แบบเดียวกับ `parseSharedBorders`**: ตัดจุดไม่ finite/นอกช่วง, ตัด ring ที่
  เหลือ < 4 จุด, ตัด boundary ที่ไม่เหลือ ring — Cesium ห้ามเจอ NaN
- ใช้เฉพาะ member `role=outer` (เขตแทรก/enclave ของ ring ใน ไม่วาด — overlay ไม่ต้องเป๊ะ
  ระดับ donut และเส้นขอบ inner จะทำให้ภาพรก)
- **cache ในหน่วยความจำ** ต่อคีย์พิกัดปัดเศษ (~1 กม.) — เปิด/ปิด toggle ซ้ำที่จุดเดิม
  ไม่ยิง Overpass ใหม่
- **dedupe ตามชื่อ** — เทศบาลที่มีทั้ง relation และ node ต้องเหลือรายการเดียว โดยขอบเขตชนะหมุด

## ความครอบคลุมของข้อมูล OSM (ตรวจจริง 2026-08-05)

ต้นเรื่อง: ผู้ใช้ชี้ว่าที่ตั้งหนึ่งอยู่ในเขต **เทศบาลเมืองแม่ฮ่องสอน** แต่แผนที่ไม่ขึ้นเส้นเขตใด ๆ

ผลค้น OSM (Nominatim + OSM API):

| เทศบาล | วัตถุใน OSM | มีขอบเขต |
|---|---|---|
| เทศบาลนครเชียงใหม่ / เชียงราย / นครราชสีมา | relation `admin_level=7` | มี |
| เทศบาลเมืองแม่ฮ่องสอน | node `place=town` | ไม่มี |
| เทศบาลเมืองน่าน / ลำพูน / พะเยา | node `place=town`/`city` | ไม่มี |
| เทศบาลเมืองแม่สาย | way `office=government` (อาคารสำนักงาน) | ไม่มี |
| เทศบาลตำบลเวียงพางคำ | node `place=municipality` | ไม่มี |

ข้อสรุปสามข้อที่กระทบการออกแบบ:

1. **ขอบเขตมีเฉพาะเทศบาลนครเป็นหลัก** เทศบาลเมือง/ตำบลส่วนใหญ่ยังไม่มี — และจังหวัดที่ขาด
   คือจังหวัดที่โครงการนี้ให้ความสำคัญที่สุด (แม่ฮ่องสอน น่าน พะเยา) จึงห้ามให้ UI พูดแทนข้อมูลที่ไม่มี
2. **`admin_level` ไม่น่าเชื่อถือ** — พบ "เทศบาลตำบลแม่จัน" ถูกแท็กเป็น level 6 (ระดับเดียวกับอำเภอ)
   จึงเปลี่ยนจากคัดด้วย `admin_level=7` มาเป็นคัดด้วย **ชื่อขึ้นต้นว่า "เทศบาล"**
3. **ชื่ออยู่คนละ tag ระหว่างสองแบบ** — relation ใช้ `name="เทศบาลนครเชียงใหม่"`
   ส่วน node ใช้ `name="แม่ฮ่องสอน"` + `official_name="เทศบาลเมืองแม่ฮ่องสอน"`
   ตัวแปลงจึงต้องอ่าน **`official_name` ก่อน** แล้วค่อยถอยไป `name`

### ผลต่อการออกแบบ

- Overpass query เป็น union 4 ชุด: relation×(name, official_name) + node×(name, official_name)
- `AdminBoundary.pointOnly` แยกว่ารายการนั้นมีขอบเขตหรือมีแค่หมุด
- เทศบาลเดียวกันที่มีทั้ง relation และ node → ขอบเขตชนะ (กันป้ายซ้อน)
- UI แสดงคำเตือน **ทุกครั้งที่เปิดชั้นข้อมูล** (ไม่ใช่เฉพาะตอนไม่พบ) ว่าข้อมูลไม่ครบ
  และให้ยึดประกาศจัดตั้ง อปท. เป็นหลักฐาน

## ภาคสอง: นำเข้าข้อมูลราชการ (2026-08-05)

ผู้ใช้สั่งให้ "นำเข้าข้อมูลขอบเขต อปท. จากกรมการปกครอง" — **ทำตามที่สั่งไม่ได้ เพราะข้อมูลไม่มีเผยแพร่**
บันทึกผลการค้นไว้เพื่อไม่ให้มีใครเสียเวลาค้นซ้ำ:

| แหล่ง | ผล |
|---|---|
| data.go.th ค้น "ขอบเขตเทศบาล" | 0 ชุดข้อมูล |
| DLA Open Data (สถ. — เจ้าของเรื่อง อปท.) | ชื่อ/รหัส/**พิกัดสำนักงาน**/ขนาดพื้นที่ ไม่มี polygon |
| COD-AB (HDX) / geoBoundaries | ลึกสุด ADM3 = **ตำบล** ไม่ใช่ อปท. |
| ชุมชน OSM ไทย | ยืนยันว่าไม่มีชุดข้อมูล อปท. สาธารณะ |
| RTSD geoportal | HTTP 403 |
| กรมโยธาธิการและผังเมือง | **จำหน่าย** ต้องติดต่อขอซื้อ |
| `municipal_wgs84_z47.zip` (บล็อก/MediaFire) | ไม่ทราบที่มา ปี และ license — ไม่ใช้ |

**ข้อสรุปเชิงหลักการ**: เขตเทศบาลเปลี่ยนตามพระราชกฤษฎีกาที่ประกาศในราชกิจจานุเบกษา
ข้อมูลที่ตรวจสอบวันที่ไม่ได้จึงใช้อ้างอิงในระบบคัดกรองงบประมาณไม่ได้ — ยอมไม่มีดีกว่ามีแบบเดาไม่ได้

### สิ่งที่นำเข้าแทน (ทั้งสองอย่างตามที่ผู้ใช้เลือก)

**1. ขอบเขตตำบล — `scripts/fetch-tambon-boundaries.mjs` → `public/geo/tambon/*.json`**

- แหล่ง: COD-AB Thailand ADM3 (RTSD เผยแพร่ผ่าน OCHA/HDX) — **CC BY-IGO ต้องแสดงเครดิต**
- 7,425 ตำบล 77 จังหวัด · ลดรูป Douglas–Peucker 50 ม. · แยกไฟล์รายจังหวัด (รหัส `TH##`)
- รวม 4.7 MB แต่เบราว์เซอร์โหลดเฉพาะจังหวัดของจุดที่ตั้ง (เฉลี่ย 61 KB สูงสุด 189 KB)
- `index.json` เก็บ bbox รายจังหวัด → client เลือกไฟล์จาก **พิกัด** ไม่ใช่ชื่อจังหวัด
  (ชื่อจังหวัดที่แผนที่รู้มาคนละแหล่งกับ COD-AB และจุดใกล้รอยต่อต้องโหลดหลายจังหวัด)
- `lib/map/tambonBoundaries.ts` — `findTambonAt` ใช้ `pointInPolygon` เดิม ตอบได้ว่า
  **"จุดที่ตั้งอยู่ ต.ใด อ.ใด"** ซึ่งเป็นสิ่งที่ชั้น OSM เดิมตอบไม่ได้เลย

**2. ทะเบียนสำนักงาน อปท. — `scripts/fetch-lao-offices.mjs` → `public/geo/lao-offices.json`**

- แหล่ง: DLA Open Data (สถ.) — Open Data Common
- ทะเบียน 7,773 แห่ง · **มีพิกัดใช้ได้ 4,816 แห่ง** (นคร 24 · เมือง 146 · ตำบล 1,428 · อบต. 3,217 · พิเศษ 1)
- ไม่เอา อบจ. (ครอบทั้งจังหวัด วาดเป็นหมุดจุดเดียวแล้วสื่อผิด)
- 873 KB โหลดครั้งเดียวต่อเซสชันแล้ว cache — `officesNear` คัดตามรัศมี 20 กม. ฝั่ง client

**กับดักในไฟล์ต้นทางที่ต้องรู้**: คอลัมน์ "ตำบล" ของ DLA เป็น **cartesian join**
(ทุก อปท. ในอำเภอถูกจับคู่กับทุกตำบลในอำเภอนั้น) ดูเผิน ๆ เหมือนเป็น mapping ตำบล→อปท.
แต่ใช้ไม่ได้ — สคริปต์จึง dedupe ด้วยรหัส อปท. แล้วทิ้งคอลัมน์นี้

### สิ่งที่ยังตอบไม่ได้ (ต้องระบุใน UI เสมอ)

ทั้งสองชั้นรวมกัน**ยังบอกไม่ได้ว่าที่ตั้งอยู่ในเขตเทศบาลหรือเขต อบต.** เพราะ:

- ขอบเขตตำบล ≠ เขต อปท. (ตำบลเดียวถูกแบ่งระหว่างเทศบาลกับ อบต. ได้)
- หมุดสำนักงานไม่ใช่ขอบเขตและไม่ใช่ใจกลางเขต
- **ห้ามเอา `areaKm2` ไปวาดวงกลมรอบสำนักงานแทนขอบเขต** — เขตจริงไม่ได้เป็นวงกลม
  และสำนักงานไม่ได้อยู่กึ่งกลาง การวาดแบบนั้นคือการกุขอบเขต

### เทสต์เพิ่ม

`lib/map/tambonBoundaries.test.ts` และ `lib/map/laoOffices.test.ts` — นอกจากเทสต์ pure แล้ว
**อ่านไฟล์จริงที่ commit ไว้** ด้วย (77 จังหวัด/7,425 ตำบล, อปท. > 4,000 แห่ง, ครบทุกประเภท,
และเคสต้นเรื่อง: พิกัดเทศบาลเมืองแม่ฮ่องสอนต้องระบุตำบลได้และต้องอยู่ในทะเบียน)
เพื่อให้ไฟล์หาย/รูปแบบเพี้ยนถูกจับตอนรันเทสต์ ไม่ใช่ตอนผู้ใช้เปิดแผนที่

### บั๊กที่เทสต์จับได้ระหว่างทำ

`Number(null)` และ `Number("")` คืน `0` ซึ่งผ่าน `Number.isFinite` — ทะเบียนที่ไม่ระบุพิกัด
จะกลายเป็นหมุดที่ (0,0) กลางมหาสมุทร และพื้นที่ที่ไม่ระบุจะแสดงเป็น "0 ตร.กม." ทั้งที่ไม่มีข้อมูล
แก้ที่ `lib/map/laoOffices.ts`, `lib/map/tambonBoundaries.ts` และตัวสคริปต์นำเข้า

## เทสต์

เพิ่ม `lib/map/adminBoundaries.test.ts` ในสคริปต์ `test` (ระบุชื่อไฟล์ตาม convention):

1. `parseOverpassAdminBoundaries` กับ fixture JSON จริงของ Overpass → ได้ชื่อ/ประเภท/rings ถูก
2. `classifyAdminKind` ครบ 4 ประเภท + ชื่อไม่เข้าเค้า → `null`
3. ring ที่มีพิกัดไม่ finite/นอกช่วง → จุดถูกตัด; เหลือ < 4 จุด → ring ถูกทิ้ง
4. relation ที่ไม่เหลือ ring ใช้ได้ → ถูกทิ้งทั้งอัน; ผลลัพธ์ว่าง → `[]` ไม่ throw
5. centroid ป้ายมาจาก ring ที่ใหญ่ที่สุด และไม่ถูกจุดปิดวงที่ซ้ำจุดแรกถ่วงน้ำหนัก
6. node ที่มี `official_name` ขึ้นต้น "เทศบาล" → `pointOnly: true`, `rings: []`, ชื่อเต็มถูกต้อง
7. node ที่มีแต่ชื่อสั้น (ไม่มี `official_name`) → ถูกทิ้ง (ห้ามเดาประเภท)
8. เทศบาลเดียวกันที่มาทั้ง relation และ node → เหลือรายการเดียวและเป็นตัวที่มีขอบเขต
9. `overpassQuery` ถามครบทั้ง 4 ชุด และไม่ล็อก `admin_level`

ตรวจปิดท้าย: `npm test` + `npx tsc --noEmit` + `npm run build` (หยุด dev server ก่อน build)
