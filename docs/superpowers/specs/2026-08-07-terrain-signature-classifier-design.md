# ลายเซ็นภูมิประเทศ (Terrain Signature) — ล็อกจิกจำแนก "ภูเขาสูงทุรกันดาร / พื้นราบในหุบเขา / พื้นราบปกติ"

สถานะ: **implement แล้ว** (`lib/terrain-signature.ts` + `lib/terrain-signature.test.ts`) — ผ่านการตรวจหักล้าง 3 มุมมองก่อนเขียนโค้ด
วันที่: 2026-08-07

## สิ่งที่เปลี่ยนจากร่างระหว่าง implement (พบตอนเขียนเทสต์)

1. **R2 ถูกกันด้วย `!isEnclosed` ทั้งกิ่ง** (ไม่ใช่เฉพาะ disjunct ที่สาม) — ก้นหุบแคบที่ผนังหุบทำให้ความลาดชันสูงจะติด `isSteep` แล้วถูกเรียกว่า "ไหล่เขา" ทั้งที่อยู่ในหลุม; การถูกล้อม = อยู่ในหุบ ไม่ใช่บนเขา เสมอ
2. **เพิ่ม `innerSlopePct`** (ความลาดชันเฉลี่ยรัศมี 500 ม.) เป็นฟิลด์ใหม่ตลอดสาย — `meanSlopeWithinRadiusPct` ใน `lib/map/morphology.ts` → `Morphology.innerSlopePct` → `GisElevationInfo.innerSlopePct` → `cleanElevation` → payload จากแผนที่ เพราะค่าเฉลี่ยทั้งกริด (~2.8 กม.) ของโรงเรียนก้นหุบถูกผนังหุบดึงให้ "ชัน"
3. **`slopeSource` + แถบความไม่แน่นอนที่กว้างขึ้น** — แถวเก่าที่ไม่มี `innerSlopePct` ถอยไปใช้ค่าเฉลี่ยทั้งกริด แต่ต้องประกาศที่มาในหลักฐาน และใช้แถบ ±4% (แทน ±2%) เพื่อให้เคสก้ำกึ่งถูกส่งให้คนตรวจแทนการตัดสินเงียบ ๆ
4. **R5 ใช้ prominence สัมพัทธ์ ≥100 ม.** แทน `isHigh` สัมบูรณ์ตามที่ร่างระบุ และ **แก้บั๊กจริงในโค้ดเดิม**: `provinceOverride?.avgElev ?? 0` ใน `morphology.ts` ทำให้ทุกจุดเหนือระดับน้ำทะเลเป็น "พื้นที่สูง" เมื่อหาแถวจังหวัดไม่พบ (แก้เป็น null-aware + `isElevationHigh` ที่ export แล้ว)

## เจตนา

ตอบคำถามเดียวให้ขาด: โรงเรียนหนึ่งแห่งเป็น **โรงเรียนถิ่นทุรกันดารบนภูเขาสูง**, **โรงเรียนพื้นราบในหุบเขา**, หรือ **โรงเรียนพื้นราบปกติ** — โดยทุกการตัดสินตรวจย้อนได้ถึงตัวเลขต้นทาง และระบบ **ปฏิเสธที่จะตอบ** เมื่อข้อมูลไม่พอ แทนที่จะเดา

## หลักการ 4 ข้อ

1. **แยกคำถามเด็ดขาด** — "ที่ตั้งเป็นภูมิประเทศแบบไหน" (landform), "เข้าถึงยากแค่ไหน" (severity 0–4), "เป็นเมืองหรือไม่" (density) เป็น 3 แกนอิสระ ห้ามยุบเป็นเลขเดียว (บทเรียนจากเครื่องมือเดิมที่ปนกันจน D = 0.04)
2. **สัมพัทธ์ ไม่ใช่สัมบูรณ์** — รูปทรงท้องถิ่นวัดจาก "สูง/ต่ำกว่าโรงเรียนเท่าไร" ไม่ใช่ "สูงจากน้ำทะเลเท่าไร"; ความสูงสัมบูรณ์ใช้เฉพาะคำถามระดับ (R1) และสิ่งกีดขวางบนเส้นทาง (routeHigh)
3. **ไม่พอข้อมูล = ตอบว่าไม่พอข้อมูล** — ทุกกิ่งมีเงื่อนไขความครบของอินพุต ไม่ครบ → ป้าย "ไม่พอข้อมูล" + รายการที่ขาด (ตามปรัชญา morphologyFromGrid ที่ throw เมื่อ DEM NaN > 10%)
4. **ทุกคำตอบแนบหลักฐาน** — rule id + ค่าอินพุตทุกตัว + ระยะห่างจากเส้นแบ่ง (margin) + ความน่าจะเป็นของ class จาก Monte Carlo

## อินพุต (ทุกตัวมี/สืบทอดจากโค้ดปัจจุบัน)

| สัญลักษณ์ | นิยาม | ที่มาในโค้ด |
|---|---|---|
| `ALT` | ความสูง terrain **ที่หมุดโรงเรียน** (ไม่ใช่ปลาย route ที่ snap) | `globe.getHeight` (เส้นทางเดียวกับ snapshot capture); fallback = route-profile end + ปักธงเมื่อระยะ snap > 300 ม. |
| `slopeInner` | ความลาดชันเฉลี่ยเฉพาะเซลล์กริดในรัศมี 500 ม. รอบโรงเรียน | กริด 41×41 เดิม กรองรัศมี (ใหม่ — กันผนังหุบปนค่า slope ทั้งผืน) |
| `nHigher` / `nLower` | จำนวน sector (จาก 8 ทิศ) ที่จุดสูงสุด ≥ ALT+50 / จุดต่ำสุด ≤ ALT−50 | `gis.sectorElevations` + `deriveSectorMetrics` (server คำนวณ delta เองอยู่แล้ว) |
| `prominence` | `local1000Elev − ALT` | `highestInRadius` เดิม |
| `routeHigh` | `routeTailMaxElev > 500 \|\| (provinceAvg ≠ null && routeTailMaxElev > provinceAvg + 150)` | แก้ `isHigh` เดิม: null-aware (บั๊ก `?? 0`) + margin 150 ม. กันจังหวัดราบต่ำ |
| `climb` | `max(0, routeFullMaxElev − ALT)` — ต้อง**ลง**มาจากจุดสูงสุดเส้นทางเท่าไร | `routeFullMaxElev` เดิม |
| `gainIn` | elevation gain สะสมตลอดเส้นทางเข้า | `sampleRouteGain` เดิม |
| `barrier` | `routeHigh \|\| climb ≥ 300 \|\| gainIn ≥ 300` | 300 = `CLIMB_K` (ค่าคงที่ใหม่ — เลขเดียวกับ band 2 ของ elevationGainSeverity แต่**คนละปริมาณ** ต้องบันทึกตรง ๆ) |
| `density1500` | ความหนาแน่นประชากรวงแหวน 1,500 ม. | **ต้องย้ายมาคำนวณฝั่ง server จาก `map_buildings`** (ปัจจุบันรับจาก client — ดู "ความจริงของโค้ด") |
| `sev` | worst-of RCR/TTR/avgSpeed/gain (derive32Severity เดิม) + รายง component | `lib/gis.ts` เดิม |

นิยามช่วย: `isFlatLocal = slopeInner ≤ 5` (LDD A/B), `isSteep = slopeInner > 12` (LDD D+), `isEnclosed = nHigher ≥ 5 && nLower ≤ 1`, `isRidge = nLower ≥ 5 && nHigher ≤ 1`

**การจับกลุ่มตามโจทย์ (แกนที่สองแสดงคู่เสมอ):**
- **กลุ่มเกาะ** = R-I เท่านั้น และ **ไม่มีทางเข้ากลุ่มอื่น** (ตรวจก่อนเกตเขตเมืองและเกตความสูง)
- **กลุ่มพัฒนาแล้ว** = R0/R0b — ถูกกรองออกจากทุกกลุ่มทุรกันดารตั้งแต่ต้นทาง
- **กลุ่มภูเขาสูงทุรกันดาร** = (R1 ‖ R2) ∧ `sevStrong` ∧ ไม่ติด R0 — โดย `sevStrong` = component อย่างน้อย 2 ใน 4 (RCR/TTR/speed/gain) มี severity ≥ 2 (กัน gain ตัวเดียวชี้ขาด: เขาค้อถนนลาดยางดีต้องไม่ติดกลุ่มนี้)
- **กลุ่มพื้นราบในหุบเขา** = R3 ‖ R4 (แสดงระดับ sev คู่กัน — ปายควรออก "หุบกว้าง × ระดับ 3–4")
- **กลุ่มพื้นราบปกติ** = R6 ‖ R6b ‖ R0
- R-I, R4b, R5, R7 มีป้ายของตัวเอง ไม่ยัดเข้า 3 กลุ่ม

| ตัวเมืองน่าน/แม่ฮ่องสอน (ในหุบแต่เป็นเมือง) | density≥750 | R0 ✓ |
| โขงเจียม (120 ม., climb 130, ราบ) | flat, climb 100–299 | R6b ✓ (v1 → "เนินเขา") |
| สันทรายปัตตานี 35 ม. | prominence 35 | R6 ✓ (v1 → "เชิงเขา") |
| เกาะพระทอง | ไม่มีเส้นทางบก | R-I ✓ (v1 → "พื้นราบปกติ"!) |

## ความจริงของโค้ด — ต้องแก้ก่อน implement (จากรีวิว code-reality)

1. **density/elevation ปัจจุบันรับจาก client** (`gis-request.ts` cast raw + clamp ช่วงเท่านั้น) — R0 ต้องคำนวณจาก SQL `map_buildings` ฝั่ง server; พิกัดศาลากลางตรวจกับตาราง `province`; `provinceAvgElev` อ่านจาก server ห้ามอ่านจาก gis blob ที่เก็บไว้
2. **`durationS` ฝั่งช้าไม่มีเพดาน** — เพิ่ม floor ความเร็วต่ำสุดที่เป็นไปได้ (กระจก `MAX_PLAUSIBLE_SPEED_KMH`)
3. **เพดานย้ายหมุด 10 กม. ทำงานเฉพาะ `syncUnitLocation:true`** — ต้องบังคับระหว่าง `gis.center` กับพิกัด `master_school` เสมอ
4. **บั๊ก `provinceOverride?.avgElev ?? 0`** ใน `morphology.ts:198` — จังหวัดหาย → ทุกความสูง > 0 เป็น "สูง"; แก้เป็น null-aware + export `isHigh`
5. **สกัดค่าคงที่ที่ยังเป็น literal**: `SETTLEMENT_SEMI_CUT = 750`, LDD flat/steep cuts (ตัดสิน `≤5` vs `<5` ครั้งเดียว), `CLIMB_K = 300` (บันทึกว่าเลขพ้องกับ band แต่คนละปริมาณ)
6. จนกว่าข้อ 1 จะเสร็จ เอกสารทุกฉบับต้องเรียกที่มาข้อมูลว่า **"client-measured, server-validated"** — ห้ามอ้าง "server อ่านอย่างเดียว"

## ชั้นความไม่แน่นอน (จากรีวิว provability — บังคับ ไม่ใช่ optional)

- **Margin ทุก predicate** ใน evidence object (เช่น "ALT 987 ม. ห่างเส้น 1000 อยู่ −13") + แถบเส้นแบ่ง: ALT ±30 ม., sector delta ±15 ม., climb ±50 ม., slope ±2 จุด, density ±20% → predicate ตัดสินในแถบ = ประทับ "ใกล้เส้นแบ่ง"
- **Monte Carlo N=200**: รบกวน DEM (σ~10 ม. correlated), หมุด ±75 ม., เส้นทาง OSRM ทางเลือก, หมุน wedge ±22.5° → รายงาน P(class); **P < 0.8 → ส่งคนตรวจอัตโนมัติ**
- **Hysteresis ข้ามปี**: เปลี่ยน class เฉพาะเมื่อ class ใหม่ยืนนอกแถบเส้นแบ่ง (กันแกว่งจาก DEM/routing update)
- **Boundary tests ทุกค่าคงที่ ±1 หน่วย** สไตล์ `tests/gis.test.ts`

## แผนพิสูจน์ v2 — "ไม่มีข้อกังขา" ต้องได้มาแบบนี้

1. **ย้อนหลัง ≠ validation**: ฐานเก่า 1,481 โรงมีแค่ citeria01 (จุดสูงสุด*เส้นทาง* ที่กรอกเอง — ไม่ใช่ ALT) จึงตรวจ tree ย้อนหลังไม่ได้; สิ่งที่ทำได้และมีค่า: (ก) batch-run pipeline จริงบนพิกัด 1,481 โรง → การกระจาย class + อัตราเคสก้ำกึ่ง (= sampling frame ของ pilot ฟรี ๆ), (ข) เทียบ DEM กับค่าที่กรอกเอง → วัดขนาด heaping 500 ม. อย่างเป็นทางการ (หลักฐาน**สนับสนุนวิธีใหม่** ไม่ใช่ validation ของ classifier)
2. **ประกาศคลัง = ตาราง cross-tab เชิงพรรณนา + คำอธิบายรายเคสทุกช่องที่ไม่ตรง** — ห้ามรายงานเป็นตัวเลข accuracy (วงจรย้อนกลับ + มันวัด "พื้นที่พิเศษ" ไม่ใช่ landform)
3. **Pilot แบบ blind (~240 โรง)**: 30 โรง/class × แบ่งชั้น stable/boundary (บังคับ boundary ~35%); ผู้ให้ป้าย 3 คนจากหน่วยงานต่างกัน เห็นเฉพาะชุดหลักฐานอิสระ (topo 1:50,000, hillshade จาก DEM คนละแหล่ง เช่น FABDEM, ภาพถ่าย) — **ไม่เห็นผล algorithm/ค่าที่โรงเรียนกรอก/สถานะประกาศ**; ประตูคุณภาพ: Fleiss κ ≥ 0.6 บน 20 anchor ก่อนเริ่ม (κ ไม่ถึง = นิยาม class มีปัญหา ไม่ใช่โค้ด); ตัดสินเคสแตกด้วย panel + ลงพื้นที่ 15%
4. **เกณฑ์รับ pre-registered ก่อนรัน**: accuracy ≥ 0.75, recall กลุ่มภูเขาสูงทุรกันดาร ≥ 0.85 / FPR ≤ 0.10, boundary-flip ≤ 5% ในกลุ่ม stable, test-retest (หมุด jitter ±50 ม. + เส้นทางสำรอง) ≥ 95%
5. **ตรวจหมุดทั้งฐาน**: `map_buildings` ไม่มีอาคารในรัศมี 150 ม. ของหมุด → ธง outlier (รันได้ทั้ง 1,481 โรงทันที); production ต้องให้โรงเรียนยืนยันหมุด (flow ลากหมุดมีแล้ว) ก่อน class เป็นทางการ
6. **Convergent validity**: geomorphon (GRASS `r.geomorphon`) บน DEM อิสระ + AI settingType (ระบุชัดว่าใช้ DEM แหล่งเดียวกับ classifier — เป็นสัญญาณเสริม ไม่ใช่ ground truth)

## สิ่งที่จงใจไม่ทำ

- ไม่แตะ 100 คะแนนทางการ / `lib/scoring.ts` / `canSubmit` — นี่คือชั้นจำแนก + หลักฐาน แบบเดียวกับ Auto GIS Score
- ไม่ใช้ขอบเขตเทศบาลเป็นเกต (ข้อมูลไม่ครบเชิงโครงสร้าง — spec admin-boundaries) — ความเป็นเมืองวัดจาก density เท่านั้น
- ไม่ใช้ prominence ตัดสิน "อยู่บนเขา" (อยู่ใกล้ ≠ อยู่บน) และไม่ให้ else-branch ใดรับโรงเรียนราบได้

## เกณฑ์ความยากลำบากของพื้นที่ 5 ระดับ (`lib/terrain-difficulty.ts`)

ชั้นนี้ต่อยอดจากตัวจำแนกด้านบน โดยยุบผลลัพธ์ให้เป็น **ระดับ 1–5** ตามข้อกำหนดของผู้ใช้งาน
ใช้สัญญาณ: ความเป็นพื้นราบ/ภูเขา · ระยะทาง · ความคดเคี้ยวของถนน · ความลาดชันขาขึ้น ·
ความเร็วที่ใช้เดินทาง · ขนาดชุมชน · และ **พื้นที่ป่า**

| ระดับ | ลักษณะพื้นที่ | คำอธิบาย |
|---|---|---|
| 1 | พื้นที่ราบ ชุมชนใหญ่ | ไม่ยากลำบาก |
| 2 | ภูเขาสูง ราบกว้างบนภูเขา ชุมชนใหญ่ | ยากลำบากเล็กน้อย |
| 3 | ภูเขาสูง ชุมชนชนบท | ยากลำบาก |
| 4 | ภูเขาสูง ชุมชนชนบท เข้าถึงยาก ≥3 ด้าน | ยากลำบากมาก |
| 5 | ภูเขาสูงสลับซับซ้อน ชุมชนชนบท | ยากลำบากที่สุด |

**"สลับซับซ้อน" ตามนิยามที่กำหนด** — มียอดเขา/หุบเขาที่ต่างระดับจากโรงเรียน **เกิน 50 ม.
มากกว่า 5 แห่ง ในรัศมี 1 กม.** นับจากธง 8 ทิศ (จุดสูงสุด + ต่ำสุดของแต่ละทิศ รวมสูงสุด 16 จุด)
→ เกณฑ์คือ `ruggedPointCount ≥ 6` (`TD_RUGGED_MIN_POINTS`) และต้องอ่านธงได้ครบ 8 ทิศ
มิฉะนั้นตอบว่า "ยังตัดสินความสลับซับซ้อนไม่ได้" ไม่ใช่ตอบว่าไม่สลับซับซ้อน

**ความเป็นภูเขาดูได้ 3 ทาง — ความสูง · ความลาดชัน · ความสลับซับซ้อน** (เจอจากข้อมูลจริงทั้งสองทาง)
โรงเรียนที่ตั้งบน "ลานราบเล็กกลางภูเขา" มีความลาดชันตรงจุดต่ำและอาจไม่สูงมาก แต่ถูกล้อมด้วยยอด/หุบ
เกินเกณฑ์สลับซับซ้อน (บ้านนาตอน: 220 ม. ลาดชันรอบตัว 5.9% แต่มี 7 จุดในรัศมี 1 กม.) — ถ้าใช้แค่
ความสูงกับความลาดชันจะได้ "พื้นที่ราบ ระดับ 1" ซึ่งขัดกับหลักฐานความสลับซับซ้อนของตัวเอง
ป้ายบอกเหตุตรง ๆ ทั้งสามแบบ: "พื้นที่ภูเขาสูง" / "พื้นที่ภูเขา (ลาดชันสูง)" / "พื้นที่ภูเขา (ภูมิประเทศสลับซับซ้อนรอบด้าน)"

**ความเป็นภูเขาไม่ได้ดูความสูงอย่างเดียว** — เขาต่ำที่ลาดชันจริงต้องไม่ถูกเรียกว่าพื้นราบ
(เคสจริงในฐานข้อมูล: บ้านนาตอน น่าน สูง 220 ม. แต่ลาดชัน 25.2% ต่างระดับพื้นที่ 378 ม.)
จึงนับ `slope > 12%` เป็นหลักฐานภูเขาอีกทางหนึ่ง และป้ายบอกเหตุตรง ๆ ว่า
"พื้นที่ภูเขา (ลาดชันสูง)" ไม่ใช่ "ภูเขาสูง" เมื่อความสูงไม่ถึงเกณฑ์

**การเข้าถึงนับเป็นรายด้าน ไม่ยุบเป็นเลขเดียว** (`TD_ACCESS_CUTS`): ถนนคดเคี้ยว ≥1.8 ·
ความเร็ว <30 กม./ชม. · เวลาเทียบพื้นที่ปกติ ≥2.0 · ไต่สะสม ≥600 ม. · ระยะทาง ≥146 กม.
(P75 ของประชากรจริง 1,481 โรงเรียน) · **สัดส่วนเส้นทางที่เป็นภูเขา ≥50%** —
ครบ ≥3 ด้าน = "เข้าถึงยากหลายด้าน"

**สัดส่วนเส้นทางที่เป็นภูเขา** (`routeMountainPercent` ใน `lib/map/routeElevation.ts`) คือ
% ของจุดตัวอย่างบนเส้นทางที่สูง ≥500 ม. — ต่างจากจุดสูงสุด (ยอดเดียวบอกไม่ได้ว่าอยู่บนที่สูงนานแค่ไหน)
และต่างจากความสูงสะสม (นับเนินเล็กรวมกันได้เยอะทั้งที่ไม่เคยขึ้นที่สูง) เก็บเป็น
`GisRouteAnalysis.mountainPct` (ใส่คีย์เฉพาะเมื่อมีค่า แถว v1 จึง round-trip เหมือนเดิม)

**พื้นที่ป่าที่ใช้หนุนต้องเป็น "สภาพป่าจริง" (`rfd-forest-cover`) เท่านั้น** — แนวเขตป่าสงวนตอบคนละคำถาม
(อยู่ในเขตประกาศตามกฎหมาย ≠ รอบตัวยังเป็นป่า) polygon เขตสงวนเดิมที่กลายเป็นชุมชนไปแล้วจึงต้องไม่ได้แต้มหนุน
ตัวแปลงอ่าน `authority` ของชั้นที่บันทึกไว้เป็น `forestSource: "cover" | "legal" | null` — ไม่ใช่ "cover" = ไม่หนุน
และแถวที่บันทึกก่อนติดตั้งชั้นสภาพป่าจะขึ้นในรายการที่ยังขาดว่า "มีแต่แนวเขตป่าสงวน — บันทึกจากแผนที่อีกครั้ง"
หลักฐานระบุที่มาเสมอ ไม่ให้ผู้อ่านเข้าใจว่าเขตกฎหมายคือสภาพป่าจริง
ผลจริงที่บ้านพญาไพร: ชั้นสภาพป่าให้ inside=1 ป่ารอบตัว 100%/96.9% → ระดับ 4 (ป่าหนุน)
ส่วนแนวเขตป่าสงวนให้ inside=0 ป่า 0%/24.7% → ระดับ 3 (ไม่หนุน) — คนละคำตอบจากโรงเรียนเดียวกัน

**พื้นที่ป่าเป็นสัญญาณหนุน ไม่ใช่ประตูตัดสินเดี่ยว** ตามที่สเปกชั้นป่ากำหนด — ดันได้ **มากสุด 1 ขั้น**
เฉพาะโรงเรียนบนที่สูงในชุมชนชนบทที่อยู่ในเขตป่าและมีป่ารอบตัว ≥60% (1 กม.) หรือ ≥50% (3 กม.)
และ **ดันได้ไม่เกินระดับ 4** — ระดับ 5 ต้องมาจากความสลับซับซ้อนของภูมิประเทศจริงเท่านั้น
ป่าอย่างเดียวยกระดับโรงเรียนพื้นราบชุมชนใหญ่ไม่ได้

ขาดความสูงที่หมุดหรือขนาดชุมชน → `level: null` ("ยังประเมินไม่ได้") เพราะทั้งสองอย่างอยู่ในนิยามของทุกระดับ
