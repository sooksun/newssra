# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Thai-language self-assessment web app for screening schools in special/remote areas (สถานศึกษาพื้นที่ลักษณะพิเศษ) to qualify for the พ.ส.ศ. allowance (2,000 THB/month). Schools enter raw facts; the app converts them to scores across 5 dimensions weighted 30/10/30/20/10 = 100 points. Total ≥ 70 → "ระดับ 3 ยุ่งยากมากที่สุด" = eligible; 60–69 = ระดับ 2 and 50–59 = ระดับ 1 (registered but not paid).

Stack: Next.js 16 (App Router, TypeScript, strict) + MySQL (`mysql2`). Deployed with Docker Compose on an Ubuntu server at `/DATA/AppData/www/newssra` (see `docs/DEPLOY.md`).

## Commands

```bash

npm run build      # production build (Next 16 → Turbopack) + type-check — run this to validate changes
npm run start      # serve the production build
npm run db:init    # create database `newssra` + tables + migrations (idempotent); app also auto-creates on first connection.
                   # Run this BEFORE deploying: it fails loudly (listing school/year/ids) if existing rows violate
                   # the one-assessment-per-school-per-year rule, which would otherwise block app startup.
npm run buildings:import  # pre-warm map_buildings with all Thailand MS footprints (one-time ~30-90 min; resumable)
npm test           # unit tests (node:test + tsx, no DB needed) — 438 cases across: scoring, gis, gis-request, map-assessment, assessment-year, snapshot views/capture, ai terrain analysis (parse), auth, rate-limit, state, uploads, app settings, map/geometry, borders, route elevation, component rendering (incl. SiteSnapshotGallery, SettingSuggestionCard, SettingsAdmin)
npm run borders:fetch     # regenerate public/geo/sea-borders.json from OpenStreetMap (needs network; ~2 min)
npm run test:integration  # route-level integration tests (needs live MySQL from .env.local; skips gracefully if unreachable)
```

Component rendering is tested the same way (node:test + `renderToStaticMarkup` from `react-dom/server`, no jsdom): `components/GisSummary.test.tsx` (evidence section, exact school-marker vs route-highest elevations, legacy rows showing "ไม่มีข้อมูล"), `components/map/GisAssessmentPanel.test.tsx` (single save button, disabled reasons), `components/map/MapPanelToggle.test.tsx`, `components/SettingsAdmin.test.tsx` (every allowlisted toggle rendered, checked state follows the value). `lib/settings.test.ts` covers the settings allowlist helpers (`parseSettingValue`, `resolveAppSettings` filling defaults and dropping unknown keys). All files are listed explicitly in the `test` script (glob-free, deterministic on Windows). No linter is configured. Local DB config lives in `.env.local` (Laragon default: root / empty password / db `newssra`). Production config goes in `.env.production` (gitignored; template in `.env.production.example`).

**Integration suite** (`npm run test:integration`, `tests/integration/*.mts`) — drives the **real route handlers against a live MySQL** to cover security logic that pure-unit tests can't: `login-route.test.mts` (enumeration parity, per-IP rate-limit → 429 + `Retry-After`, success sets the `pss_session` cookie) `assessment-security.test.mts` (`canAccessAssessment` scoping through GET/PUT/`/gis`, PUT preserving server-owned `submitted`/`evidence[].files` against a forged client payload, and the `/gis` 409 submit-lock), `map-to-assessment.test.mts` (the `/from-map` endpoint end-to-end: created→updated→locked on one school-year row, the locked row staying byte-identical, master-data prefill and blank-field fill on an existing draft, the >10 km relocation 409, role/auth gating, and a forged `schoolCode` in the body having no effect), `assessment-year-conflict.test.mts` (the school-year unique key surfacing as 409 on the legacy create/autosave routes), and `admin-settings.test.mts` (`PATCH /api/admin/settings`: admin writes the row for real, a school session gets 403, an out-of-allowlist key gets 400; `after()` deletes the row so the system returns to defaults). Mechanics: files are `.mts` (ESM, so top-level `await` + `mock.module` work) and run with `--experimental-test-module-mocks --test-force-exit`; `tests/integration/_setup.mts` mocks **only** `next/headers` so `getSession()` reads a session we sign with the real `signSession` (`actAs(user)`), while DB/repo/sanitize/rate-limiter all run for real. Test rows use `owner_school_code` prefixed `TEST*` and are cleaned up in `after()` (the map-to-assessment file additionally seeds and removes temporary `master_school`/`school_location` rows, since `/from-map` reads school name/coords from that registry). Integration files run as **concurrent processes against the same DB**, so fixtures must not collide across files — keep per-file-unique school codes and `submitted_ref` values. If MySQL is unreachable every test **skips** (never fails) so it stays CI-safe and the `npm test` "no DB needed" contract is untouched. The `--test-force-exit` flag is required because the lazy `mysql2` pool keeps an open handle after the run.

Don't run `npm run build` while a `npm run dev` server is running against the same folder — both write to `.next/` and will corrupt each other's cache (manifests as `Cannot find module './NNN.js'` on next dev requests). Stop the dev server first, or just delete `.next/` and restart dev if this happens.

To manually test: open the list page, create an assessment, and use the "เติมตัวอย่าง ▾" dropdown — pick any of the 5 sample profiles (see `lib/demo.ts`). Expected totals: boundary-pass=70 (ระดับ3, V09), severe-remote=98 (ระดับ3, V07), borderline-review=68 (ระดับ2, V09), level1-notpaid=55 (ระดับ1, no flags), urban-fail=12 (neutral, no flags).

## Architecture

Data flow: client form state → debounced PUT → server recomputes scores → MySQL. The DB row stores the full `state` JSON (source of truth) plus summary columns (`total_score`, `level_key`, `unit_name`, …) that the server derives on every write for the list page — never write summary columns from client-supplied values.

- `lib/types.ts` — shared types; `INDICATOR_IDS` (15 ids `"1.1"`…`"5.2"`) and `AssessmentState` (unit / responses / evidence / feedback / signed / submitted, plus **optional** `gis?: GisAnalysis` + `scoringVersion?: "v2-gis"` — both absent on v1 rows; see the GIS layer below).
- `lib/criteria.ts` — `DIMENSIONS` + `INDICATORS`: single source of truth for criteria text, max scores, level options, evidence requirements. Indicator `kind` is either `"fields"` (raw inputs) or `"level"` (pick-one options; the selected option **index** is stored as a string in `responses[id].level`). Each `IndicatorDef` also carries a `desc` (plain-language explanation) and, for `"fields"` indicators, a `criteria` string list (the score bands) — these feed the per-indicator hover **"?" info popup** in `DimensionPanel.tsx` (`.info-icon-wrap` → `.info-popup`, shown on hover/focus/focus-within, keyboard-reachable via `tabIndex={0}` + `role="tooltip"`), which shows title + `desc` + the bands (for `"level"` indicators it lists `label = points คะแนน` per option instead) + the evidence requirement, so reviewers don't cross-reference the spec doc while scoring. Hidden in print (`.info-icon-wrap { display:none }` in the `@media print` block).
- `lib/scoring.ts` — pure scoring engine: `scoreIndicator` (the per-indicator switch), `flags` (validation flags), `levelFor`, `canSubmit`, `computeAll`. Used by both the client (instant UI) and the server (authoritative recompute on save/submit) — keep it framework-free. `flags()` also imports `derive32Severity`/`primaryRoute` from `lib/gis.ts` for the GIS flags V11/V12/V14/V19/V20 (all guarded by `if (state.gis)` so v1 rows get the identical legacy flag set); every GIS flag is `info`/`warn` only, so `canSubmit` (which blocks only on `block`) is unchanged.
- `lib/state.ts` — `makeBlankState(year = currentBuddhistYear())`/`sanitizeState`. Every payload entering the server passes through `sanitizeState` (drops unknown keys, coerces types, caps lengths). `sanitizeState` is a **strict allowlist** rebuilt from `makeBlankState`, so any new top-level field is dropped on read/save unless explicitly whitelisted — the `gis`/`scoringVersion` fields are handled by a `sanitizeGis(raw.gis)` clause (delegated to `lib/gis.ts`); `makeBlankState` still emits no `gis` key, so v1 rows round-trip byte-identically.
- **Evidence file uploads:** `EvidenceInfo.files: EvidenceFile[]` (`lib/types.ts`) holds metadata only (id, originalName, mimeType, size, sha256, uploadedAt) — the actual bytes live on the filesystem under `uploads/{assessmentId}/{indicatorId}/{fileId}` (`fileId` is a UUID and doubles as the on-disk filename, so no path ever depends on a user-supplied string). `lib/uploads.ts` (server-only: uses `node:fs`/`node:crypto`) does the disk I/O; `lib/upload-constants.ts` holds the shared allow-list/size-cap constants that both `lib/uploads.ts` and the client-safe `lib/state.ts`/`DimensionPanel.tsx` need, specifically so `lib/state.ts` (imported by the client component `AssessmentForm.tsx`) never pulls in `node:fs`. Upload/view/delete go through their own routes (`app/api/assessments/[id]/evidence/[indicatorId]/route.ts` and `.../[fileId]/route.ts`) instead of the general autosave PUT, since files can't travel through a JSON body — after a successful call, the client folds the returned metadata into `state.evidence[id].files` via the existing generic `onEvidence` patch handler (no new handler type needed). Allowed types: JPEG/PNG/WebP/PDF, 10MB/file, 10 files/indicator — enforced both client-side (`accept`, disabled state) and server-side (the actual gate). Deleting an assessment (`app/api/assessments/[id]/route.ts` DELETE) also calls `deleteAllEvidenceFiles()` so its upload folder doesn't linger on disk. Hidden in print like the rest of `.evidence-box`.
- **GIS analysis layer (v2, "prove remoteness from the map"):** `lib/gis.ts` is a **pure, framework-free** engine (client+server shared, like `lib/scoring.ts`; imports only `lib/types.ts` + `haversineM` from `lib/map/morphology.ts` — must **not** import `lib/scoring.ts`, since scoring imports it). It computes **Road Circuity Ratio** (road ÷ straight), **Travel Time Ratio** (actual ÷ reference at `REFERENCE_SPEED_KMH=60`), **Effective Distance** (road × TTR), average speed, and cumulative **elevation gain/loss** (`elevationGainLoss`, 3 m noise floor); maps each to a 0–4 **severity** via `GIS_BANDS` tables (RCR/avg-speed verbatim from the PRD); builds the informational **Auto GIS Score** (`computeAutoGisScore`, max 45 — shown honestly as "X / maxComputable (จากเต็ม 45)" since border/municipality data doesn't exist yet, so those components stay `null` and aren't counted); and exposes `sanitizeGis` + Thai plain-language explainers. **Scoring v2 works by writing derived values *into* `responses["3.1"/"3.2"/"3.3"]`** (`deriveD3Responses`) so the **existing** `scoreIndicator` switch scores them with zero engine changes — 3.1 from the district-office-or-province-hall route's minutes/km, 3.2 from `derive32Severity` (worst-of RCR/TTR/speed/gain → option index 0–4), 3.3 only if a hospital route was picked (else left manual). **Two write paths, one shared processor:** the map's normal one-button flow posts to **`POST /api/assessments/from-map`** (see the map-to-assessment flow below), while the older **`POST /api/assessments/[id]/gis`** stays for an already-open assessment (`requireAssessmentAccess`, so admin/ssra can use it too). Both delegate payload parsing to **`lib/gis-request.ts#buildGisFromMapRequest`** (framework-free, unit-tested) which copies only raw fields from the client (`destinationType`/`destinationName`/`destLat`/`destLng`/`roadDistanceM`/`durationS`/`elevationGainM`/`elevationLossM`/`selected`/`highestPoint`) and recomputes every ratio server-side — no client ratio, score, community class or timestamp is ever retained. It throws `GisRequestError` with codes `INVALID_CENTER`/`INVALID_GIS` (→400) and `NO_VALID_ROUTE` (→422, only when the caller passes `requireProvinceRoute: true`, which `/from-map` does and `/gis` doesn't). The `/gis` route keeps its own guards (**409 after submit**; drops physically-impossible routes; **409** when a re-centre would move `unit.lat/lng` more than `MAX_ASSESSMENT_RELOCATION_M` = 10 km; fills `center.nearestProvinceName` via `listProvinces`+`resolveSchoolProvince` (the school's **registered** province from `master_school.provinces` first, then the entered province, then nearest-hall fallback — so V11 stops false-firing for border districts); applies `deriveD3Responses` + sets `scoringVersion:"v2-gis"` when `apply:true`). **Elevation contract:** `GisElevationInfo.schoolMarkerElevationM` is the elevation **sampled at the school end of the route profile** — never the area mean (`meanElevationM` is a separate field, alongside `minElevationM`/`maxElevationM`/`reliefM`/`maxSlopePct`/`localMaxElevation1KmM`). `sanitizeGis` still reads the pre-v2 key `schoolElevationM` and emits it as `schoolMarkerElevationM`, so legacy rows keep working, but nothing may write the mean into that field again (`tests/route-elevation-flags.test.ts` guards the CesiumMap source against it). `GisRouteAnalysis.highestPoint`, `GisAnalysis.radiusSummaries` (500/1,000/1,500 m rings) and `GisAnalysis.dataSources` (terrain/routing/buildings + `analyzedAt`) are optional and only attached when validation succeeds, so v1 rows stay key-free. **Informational-only extras** (never part of the official 100): `futureIndicators(gis)` returns the two proposed criteria **F1 Displacement Ratio** (straight ÷ road, severity reusing the RCR bands so they can't drift) and **F2 Travel Time Ratio**, rendered in `GisSummary` under "เกณฑ์เสนอเพิ่ม (อนาคต) — ไม่นับรวมในคะแนน 100". The general autosave PUT (`app/api/assessments/[id]/route.ts`) treats `gis`/`scoringVersion` as **server-owned** — preserved-from-DB like `submitted`/`evidence[].files`, via conditional spread so v1 rows stay key-free. `components/GisSummary.tsx` renders the read-only section **"ข้อมูลประกอบเกณฑ์จากแผนที่ 3 มิติ"** in the assessment form: terrain group (school-marker elevation and route-highest point **shown separately**, the latter with its coordinates — same values the two red flags render on the map), route metric table, radius-ring table, polygon area summary, community class, Auto GIS Score, the F1/F2 future-criteria table, the GIS-vs-current D3 comparison that V19/V20 flag, and the data-source list with `analyzedAt` formatted in Asia/Bangkok. Missing values render **"ไม่มีข้อมูล"** (`valueOrMissing`) — never a substituted stand-in; it shows an invite line when `state.gis` is absent. Hidden-in-print rules keep the tables but drop `.gis-actions`. `lib/demo.ts`'s `severe-remote` profile carries a consistent `gis` blob (total stays 98, no V19/V20).
- **3D site snapshots + AI terrain analysis:** from the map (assessment mode) a school can press **"📸 จับภาพ 3D ยืนยันที่ตั้ง"** to auto-capture **9 fixed camera views** (`lib/map/snapshotViews.ts` — top-down + near/far × N/E/S/W; pure, tested) of the school point. The Cesium `Viewer` sets **`preserveDrawingBuffer: true`** (mandatory — without it `canvas.toDataURL()` returns a blank image); `lib/map/snapshotCapture.ts` (client-only) flies each view, waits for tiles via **`setTimeout` polling not rAF** (so a backgrounded tab can't hang the loop forever), and captures JPEG 0.85. The 9 blobs POST to **`POST /api/assessments/[id]/site-snapshots`** (`requireAssessmentAccess`, **409 after submit**, image-only via `sniffMimeType` — PDF rejected, replaces the whole set atomically: validate all → delete old → write new → save). Bytes live under `uploads/{id}/__site/{fileId}` (`lib/uploads.ts` `saveSiteSnapshot`/`readSiteSnapshot`/`deleteAllSiteSnapshots`; folder starts `__` so it never collides with an `indicatorId`; `deleteAllEvidenceFiles` already removes the whole `uploads/{id}/` tree). Metadata is `SnapshotFile[]` in **`state.unit.siteSnapshots?`** — **server-owned** (like `evidence[].files`: `sanitizeState` caps at `MAX_SITE_SNAPSHOTS=9`, `preserveServerOwned` restores from DB so autosave can't forge it; `makeBlankState` omits the key so v1 rows round-trip). `components/SiteSnapshotGallery.tsx` renders the thumbnails (served by `GET .../site-snapshots/[fileId]`) under "ลักษณะที่ตั้ง" in `UnitPanel`, hidden in print. **After a successful capture the client auto-calls `POST .../site-snapshots/analyze`** (best-effort — navigation to `/assessment/{id}#unitPanel` happens whether it succeeds or fails): the route reads the 9 stored images and sends them to **OpenRouter (Google Gemini 2.5 Flash)** via **`lib/ai/terrainAnalysis.ts`** (server-only, plain `fetch` — no SDK dependency; reads `OPENROUTER_API_KEY`, model from `AI_TERRAIN_MODEL` default `google/gemini-2.5-flash`) which uses OpenAI-compatible `image_url` data-URL content + a **`response_format: json_schema` strict** shape, and a Thai prompt that **forbids identifying individuals (PDPA)**. It returns `{settingType, rationale, confidence}`; `settingType` is validated against `SETTING_TYPES` in **three layers** (json_schema enum → `parseTerrainResponse` → `cleanSettingSuggestion`). The route adds `analyzedAt` and stores **`state.unit.settingSuggestion?: TerrainSuggestion`** (also server-owned; same sanitize/preserve pattern). `components/SettingSuggestionCard.tsx` shows "🤖 AI แนะนำ…" with a **"ใช้ค่านี้"** button that fills `settingType` only on click — **never auto-overwrites** the reviewer's choice (a second signal alongside `suggestSettingTypeFromGis`). The AI never runs on a submitted assessment (**409** first), never receives school/student data (only terrain images), and the key is server-only (never imported by a client component, never echoed in a response). The endpoint is per-user rate-limited (`terrainAnalyzeRateLimiter`, 10/hr, mirrors the `/api/buildings` `check→429+Retry-After→fail` pattern). `OPENROUTER_API_KEY` is **optional** — unset → the analyze route returns 401 and the card simply never appears; capture and everything else work unchanged.
- **3D map (`/map`, ported from the GeoCommunity Classifier geotech project):** a trimmed, **keyless** CesiumJS terrain map that is the post-login landing page. `app/map/page.tsx` (server) `requireUser()`s, then computes the center: `school` users center on their assessment with valid `unit.lat/lng`, falling back to the registered coords from `master_school`/`school_location` (`lib/repo.ts#latestOwnerCoords`/`schoolLocationByCode`), while `admin`/`ssra_admin` get a national top-down view (they aren't tied to one school). The Cesium viewer is browser-only, so it loads via `components/map/CesiumMapLoader.tsx` (`next/dynamic`, `ssr:false`) → `components/map/CesiumMap.tsx` — never import `cesium` from a server component or it leaks into the server bundle. Keyless stack: Terrarium terrain (AWS Open Data) + Esri World Imagery, no token (optional `NEXT_PUBLIC_CESIUM_ION_TOKEN` upgrades to Ion). Ported client-safe libs live in `lib/map/` (`cesium-config`, `cesiumTerrain`, `morphology`, `geometry` [pure geo math — `pointInPolygon`/`polygonCentroid`/`polygonBoundingRadiusM`/`polygonAreaM2`; tested in `lib/map/geometry.test.ts`, now wired into `npm test`], `esriImagery` [imagery-URL probe, see `scripts/probe-esri-imagery.mjs`], `msBuildings` [Microsoft building-footprint helper], `placeSearch`, `mapApi` [the map's network layer — `fetchOsrmRoutes`/`fetchBuildings`/`fetchNearestProvince`, pure functions that throw on failure so `CesiumMap` can surface the error via its own state; extracted from `CesiumMap.tsx` to dedupe the OSRM calls]). Province avg-elevation (a scoring input for the mountain/valley classification) comes from the DB `province` table via `lib/repo.ts#listProvinces`, passed into `morphologyFromGrid` as `provinceOverride`. **Which province a point belongs to** is resolved by `resolveSchoolProvince` (registered `master_school.provinces` keyed by the 8-digit school code → the user-entered `unit.province` → `nearestProvince` nearest-hall fallback): matching by nearest provincial hall alone is wrong for border districts (e.g. อ.ฝาง in เชียงใหม่ sits closer to the เชียงราย hall), so a school's registered province wins for the school's **home point**. `/api/provinces/nearest` (called on drag/search re-center) resolves in priority order: **(1) a `province` hint** — the actual province of the moved-to point, sent by the client from the search result's geocode `address_components` (Google) / `addressdetails` (Nominatim), or a Nominatim **reverse-geocode** on drag (`reverseProvince` in `placeSearch.ts`), matched via `provinceByName` so the province *follows where the user searched/dragged* instead of sticking to the logged-in school; **(2)** the school code from the **trusted session** (school viewers) or an accessible `?assessment=ID` owner (never a raw client school code — no spoofing) via `resolveSchoolProvince`; **(3)** nearest-hall fallback — there is no `/api/provinces` fetch or bundled fallback table (the old geotech `provinceElevation` stub was removed as dead code). **Cesium static assets:** `scripts/copy-cesium.mjs` copies `node_modules/cesium/Build/Cesium/{Workers,Assets,ThirdParty,Widgets}` → `public/cesium/` (gitignored) via the `predev`/`prebuild` npm hooks; the component sets `window.CESIUM_BASE_URL="/cesium"` and loads `widgets.css` through a `<link>` (not a webpack import, to avoid asset-resolution build failures). The full geotech features (routes, saved results) were intentionally dropped — they need geotech's backend + tokens. **Place search** is a client-side port of geotech's logic in `lib/map/placeSearch.ts` (`searchPlaces`/`resolvePlaceHit`): it lazy-loads the **Google Maps JS SDK** (`loadGoogleMaps`, injects one `<script>` with `libraries=places,geometry`, `language=th`, `region=TH`, keyed by `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`), uses **`AutocompleteService`** to show a live debounced (≥3 chars, 450 ms) suggestions dropdown, and resolves the picked `place_id`→coords via `Geocoder` only on selection — with **Nominatim/OpenStreetMap fallback** throughout (client-side `fetch`; OSM allows CORS) so the map stays keyless-functional (`googleGeocoderAvailable` latches off after `REQUEST_DENIED`/`ApiNotActivated`). The Google key needs **Maps JavaScript API + Places API** enabled (in addition to Map Tiles API for imagery). `CesiumMap.tsx` owns the UX (`runSearch`/`onSearchChange`/`pickResult`, out-of-order guard via `searchSeqRef`) and drops a temporary pin in the `search` `CustomDataSource`. There is **no** `/api/geocode` server route — search is fully client-side, matching geotech. Building footprints still go through `app/api/buildings/route.ts` — **fast since v2**: `lib/map/msBuildings.ts` streams each Microsoft quadkey file **once ever**, persists centroid+area+height into app-owned `map_buildings` (+`map_buildings_meta`, index `(quadkey, lat)`; `CREATE TABLE IF NOT EXISTS` lazily), and serves every later request from a SQL bbox query (~0.3s vs ~2-4 min re-stream; survives restarts, shared across processes). Returned rings are **synthetic squares sized from each building's real area** (storing real rings for 18M buildings would cost GBs; the tool only counts buildings → population). The bbox pulls **all intersecting quadkeys** (up to 4 at tile edges — fixes an old undercount). Pre-warm all of Thailand with `npm run buildings:import` (resumable; `--force`, `--quadkey QK`). If the DB is unusable the old stream+in-memory-cache path still works as fallback. The legacy geotech `buildings`/`ms_buildings` tables are **not used** (partial bbox-filtered imports, unreliable counts — e.g. Fang quadkey: 24k rows there vs 312k real). **Re-centering:** picking a result only drops a temporary purple pin + flies the camera (does not move the analysis point yet); a **"ยืนยันใช้พิกัดใหม่นี้"** button then appears under the search bar, and confirming moves the analysis point there and recomputes everything. **Dragging the pin:** the red center pin (`id: "center-pin"`, ref `centerPinRef`) is draggable directly on the globe — a `ScreenSpaceEventHandler` picks it on `LEFT_DOWN` (locks the camera via `screenSpaceCameraController.enableInputs=false`), follows the cursor on `MOUSE_MOVE` (`scene.pickPosition`→`ConstantPositionProperty`), and on `LEFT_UP` re-centers immediately (no confirm step). The morphology (main calc) always samples the real terrain grid at the new center regardless. **Collapsible side panel:** the analysis panel (`#cesium-map-panel`) can be folded away with `components/map/MapPanelToggle.tsx` (`panelExpanded` state in `CesiumMap.tsx`, `.map-panel-toggle*` in `globals.css`) so the globe gets the full width on small screens; `tests/map-panel-collapse.test.ts` pins the wiring. **Map → assessment (one button):** a `school` user always sees the analysis panel with the single primary action **"บันทึกข้อมูลประกอบเกณฑ์และกรอกแบบประเมิน"** (`components/map/GisAssessmentPanel.tsx`) — no `?assessment=ID` needed and no checkbox: one POST to `/api/assessments/from-map` **creates or updates that school's current-year assessment**, fills the master-data fields, applies Dimension-3 scoring server-side, then navigates to `/assessment/{id}`. `app/map/page.tsx` resolves the row **year-specifically** (`currentBuddhistYear()` + `lib/repo.ts#assessmentForSchoolYear`) and passes `canSaveAssessment = role is school && has schoolCode`, independent of whether a row exists yet. In every non-national mode the map draws the amber dashed **straight-line overlay** vs. the road route, samples cumulative **elevation gain** along the *full* route (`sampleRouteGain`, downsample 120) plus the route-elevation profile that feeds both red flags (school marker + highest point, `lib/map/routeElevation.ts`), shows the per-route **GIS metrics panel**, and lets the user tag extra **destinations** (district office / hospital) picked from the existing place search (green pins, own `gisDest` `CustomDataSource`). The area summary rides along in the **same single save** (there is no separate "ส่งข้อสรุปพื้นที่" button any more): it travels as `areaSummary` in the `/from-map` payload, is stored as `gis.areaSummary` (`GisAreaSummary`; the server recomputes `settlementLabel` from population density rather than trusting the client) and rendered in `GisSummary`. Data already saved is not lost when a later payload omits it — `applyMapGisToState` carries forward the previous `areaSummary`/`radiusSummaries`, and the `/gis` route does the same for its own callers. The polygon-draw click handler guards against `pickPosition` returning a `NaN`/non-finite coordinate (horizon/off-globe clicks) — a `Number.isFinite` check skips the vertex, since a NaN vertex otherwise crashes Cesium's polygon renderer ("cartesian has a NaN component") and makes `polygonAreaM2` return NaN. **Radius rings:** a `rings` datasource auto-draws 3 concentric circles (`RING_RADII_M = [500,1000,1500]` m, green/yellow/red, via `circleCoords`) around the analysis center whenever `!national`; it calls `fetchBuildings(..., RING_RADII_M)` (the `rings` query param → `ringCounts` cumulative-per-radius from `msBuildings.ts`) and shows a table of buildings + est. population (× province household size) + density per ring, then classifies the surrounding **community type** via `settlementClass(outer-ring density)` — this is the ring-based settlement summary shown in the panel. **International borders:** `public/geo/sea-borders.json` (~228KB committed) holds the **pre-computed** land border Thailand shares with each of its 4 land neighbors — one continuous chain per country, plus a label position and the ODbL attribution string. It is drawn by the `borders` datasource as `clampToGround` polylines + Thai country-name labels, toggled by `showBorders` (default on); `proxy.ts` excludes `/geo` from the auth gate so the static file serves without a redirect. `lib/map/borders.ts#parseSharedBorders` only **validates** the loaded file (drops non-finite/out-of-range coords and chains under 2 points so Cesium can't crash mid-draw) — no geometry is derived at runtime. **Regenerate with `npm run borders:fetch`** (`scripts/fetch-borders.mjs`): it asks Overpass for the ways that belong to **both** Thailand's and the neighbor's `admin_level=2` relation — in OSM an international boundary is a single shared way, so this yields the shared border exactly, with no coordinate matching needed — drops maritime ways (`maritime=yes` / `border_type=territorial`, otherwise long straight sea segments leak in), chains the ways end-to-end, simplifies with Douglas–Peucker (default 50 m, `--tolerance`), and rounds to 5 dp. Result: median vertex spacing 304–496 m and 57–342 m deviation at real border crossings. **Do not go back to Natural Earth 1:10m** — that was the original source and it is a world-atlas-scale generalization (median spacing ~2 km, straight jumps up to 23 km, measured 0.7–3.2 km off at real crossings), which is unusable at this map's 500–1500 m ring zoom. Data is **ODbL**, so `CesiumMap.tsx` must keep rendering the `attribution` string ("© OpenStreetMap contributors") whenever borders are shown. `lib/map/borders.test.ts` guards the bundled file: one chain per country, length within 5% of the official figure, median spacing < 700 m, and the tri-points (สามเหลี่ยมทองคำ, ช่องบก) meeting within 100 m. **Route rendering:** the selected route uses `clampToGround: true` (ground polyline draped on terrain — always visible on the surface). A previous experiment lifting it to `terrainHeight+25 m` was **reverted**: an elevated polyline can't disable depth-test, so intervening terrain occluded it and it appeared to vanish in valleys — the clamped ground polyline is the reliable choice. To pre-warm ring/area building data so it's instant, run `npm run buildings:import`.

## Domain Rules (from the spec — do not violate when touching scoring)

The authoritative spec is `docs/ข้อเสนอเกณฑ์และตัวชี้วัด-พสศ-v1.md`: per-indicator scoring tables in §4 (use the "เสนอ" column), cut-off logic in §5, roles/data model/workflow for the intended full system in §8, validation flags V01–V10 in §8.5. Implemented flags: V02, V04, V06, V07, V09 + app-local V00 (count > total students) + the GIS-only set V03 (manually-entered 3.1/3.3 travel time > 50% above the GIS route's `travelTimeMin`), V11 (pin nearest a different province hall than `unit.province`), V12 (road < straight distance), V14 (RCR > 3), V19/V20 (GIS-derived vs. manually-picked 3.2 severity differ by ≥2) — the GIS flags fire only when `state.gis` exists and are `info`/`warn`, never `block`. Tone `"block"` prevents submission. **Deliberately NOT implemented (need a data source the app doesn't collect):** V01 (deviation from a central enrollment DB — no central reference), V05 (photo GPS > 5 km from school — evidence files store no EXIF/GPS), V08 (dimension-5 answer vs a central registry — no such registry), V10 (uploaded file "looks like a personal name list" — needs content classification, only magic-byte sniffing exists). Don't fake these — they require the missing data before they can fire faithfully.

- Users enter raw data only (counts, minutes, level selections) — never add an input where a user types a score directly, and never trust client-computed scores (server recomputes via `lib/scoring.ts`).
- Normal conditions = 0 points; no free base points anywhere.
- Score ranges follow "เกิน a – ไม่เกิน b" (exclusive lower bound, inclusive upper), with no gaps or overlaps; percentages use 2 decimal places.
- PDPA: student data is aggregate totals only — the app must never collect or accept individual student name lists (ethnicity, poverty, disability, and registration status are sensitive data). Keep everything utf8mb4.
- **Authentication + 3 roles are implemented, with hybrid login.** `admin` (see/edit all + user management), `ssra_admin` (see/edit all), `school` (see/edit only their own school's assessments). No new deps: `lib/auth.ts` (server-only) does scrypt hashing + an HMAC-signed httpOnly session cookie via `node:crypto`; `lib/auth-constants.ts` holds the edge-safe cookie-name constant so `proxy.ts` (Next 16's renamed middleware convention — redirects unauthenticated page requests to `/login`) never imports `node:crypto`. **Two account sources (login tries them in order):** (1) `lib/users-repo.ts` `users` table — local admin/ssra_admin accounts (scrypt-hashed), seeded on first DB connect via `seedDefaultUsers` (only `admin`+`ssra_admin`; **schools are NOT seeded here**); (2) `lib/legacy-users-repo.ts` reads the pre-existing legacy `` `user` `` table (~3,158 real school logins from the old SSRA system, keyed by an 8-digit `user` code, **plaintext passwords 5–6 chars** — compared directly; note the security caveat). A legacy match becomes a `school` session with `schoolCode` = the 8-digit code, and triggers **lazy migration** (see the migration note below): a scrypt-hashed row is written to the `users` table so subsequent logins use the hashed path, not the plaintext one. **Session** (`SessionUser`) carries `{uid, role, name, source: "local"|"legacy", schoolCode}`. **School scoping is by school code:** assessments carry `owner_school_code` (+ `owner_user_id`), `lib/repo.ts#listAssessments(viewer)` filters `school` viewers by `owner_school_code = viewer.schoolCode`, and `canAccessAssessment(user, ownerSchoolCode)` gates single rows (empty schoolCode ⇒ sees nothing; `null !== ""` guards blank owners). Local `users` rows can also hold a `school_code` (set via the admin UI). **Admin user management** (admin-only) lives at `app/admin/users/page.tsx` (`requireRole("admin")`) + client `components/UsersAdmin.tsx`, backed by `app/api/admin/users/route.ts` (GET list / POST create — username must match `^[a-zA-Z0-9_.-]{3,64}$`, password ≥6 chars, duplicate username → 409) and `app/api/admin/users/[id]/route.ts` (PATCH `role`/`displayName`/`active`/`password`/`schoolCode`). A `countAdmins(true) <= 1` guard blocks demoting or deactivating the **last active admin** (so you can't lock yourself out); there is no hard-delete — accounts are just deactivated (`active=false`). This UI manages **local `users`** — including school accounts that have been **migrated** from legacy on their first successful login (once migrated they appear here and an admin can reset the password / deactivate them); un-migrated legacy 8-digit logins don't appear until their first login. `components/UserMenu.tsx` is the top-right name/role dropdown with logout (POST `/api/auth/logout`), hidden in print. Columns are migrated in `lib/db.ts#init()` via `information_schema` checks (MySQL 8 lacks `ADD COLUMN IF NOT EXISTS`). **Guard pattern:** pages use `requireUser()`/`requireRole(...)` from `lib/auth.ts`; API routes use `requireApiUser()`/`requireApiRole(...)`/`requireAssessmentAccess(id)` from `lib/api-auth.ts` (returns `{ok,response}` — return `guard.response` on failure). The legacy `` `user` `` table is **read-only** to this app (never written/altered; `user` is a MySQL reserved word so always backtick it). `AUTH_SECRET` (env) signs sessions — dev falls back to a default **with a warning**, but **production throws (fail-closed) via `authSecret()` if it's missing, `<16` chars, or equal to the dev default** (every request touching a session fails until it's set). Seed passwords behave similarly: dev defaults to `admin123`/`ssra123`, but production **auto-generates a strong random password and logs it once** when `SEED_ADMIN_PASSWORD`/`SEED_SSRA_PASSWORD` are unset (no known-weak default on prod). **Login is rate-limited** (`lib/rate-limit.ts` — in-memory fixed-window `RateLimiter`, 10 fails / 15 min → 15-min block, checked per-IP *and* per-username; returns 429 + `Retry-After`; IP taken from `x-forwarded-for`/`x-real-ip`, skipped when unresolvable so one shared key can't lock everyone out; success clears the counters). **Legacy plaintext passwords migrate to scrypt lazily on successful login** — a hashed `users` row is created (the read-only `` `user` `` table is never written), with a **self-healing rehash** path for `school` accounts if the legacy password later changes; full rationale + phases in `docs/AUTH-MIGRATION.md`. Trade-offs: stateless cookie ⇒ deactivation takes effect next login (7-day expiry); rate-limit state is in-process (resets on restart, not shared across instances — swap for a shared store if scaling out).

## Deployment

`Dockerfile` (multi-stage, standalone output) + `docker-compose.yml` (app on host port 9950 → container :3000 + MySQL 8.4 with data bind-mounted at `./data/mysql`, uploaded evidence files at `./data/uploads` → container `/app/uploads`). Both services read `.env.production`. Full runbook in `docs/DEPLOY.md`, including the variant that points at an existing host MySQL via `host.docker.internal`.

**Run `npm run db:init` against the target database before cutting over.** The `uq_owner_school_year` migration is fail-closed: if the existing data already holds more than one assessment for the same school and year, `init()` throws on every request (the app, including the admin UI, stays down) until the duplicates are merged or deleted by hand. Running `db:init` first surfaces the exact `school / year / ids` groups while the old version is still serving.
